# 🐙 Octopus Escape

Кооперативная стелс-игра для 1–2 игроков по сети. Осьминоги — подопытные в лаборатории — пытаются сбежать: хватают всё щупальцами, прячутся, меняют окрас и уворачиваются от охранников.

- Дизайн игры: [docs/GDD.md](docs/GDD.md)
- План и прогресс: [ROADMAP.md](ROADMAP.md)
- Вся документация: [docs/README.md](docs/README.md)

## Установка проекта

> Команда работает на **Ubuntu и Windows** одновременно. Всё ниже работает на обеих системах. Для Windows есть отдельные пункты.

### 1. Настроить Git (один раз на компьютере)

```bash
git lfs install
```

Без этого вместо моделей и текстур скачаются пустые файлы-заглушки, и в Unity всё будет розовым или пропадёт.

**Только на Windows** дополнительно выполни:

```bash
git config --global core.autocrlf false
git config --global core.longpaths true
```

- `core.autocrlf false`: переводами строк управляет файл `.gitattributes` в проекте (везде `LF`), и git не должен вмешиваться. Иначе у второго участника все файлы будут выглядеть изменёнными.
- `core.longpaths true`: снимает ограничение Windows в 260 символов на путь. У Unity бывают очень длинные пути.

### 2. Скачать проект

**На Windows** клонируй проект в короткий путь, например `C:\Projects\`. Не клонируй в `Documents`, на рабочий стол или в OneDrive: длинные пути и синхронизация OneDrive ломают Unity.

```bash
git clone git@github.com:Bogban893/Octopus_escape.git
```

Если SSH-ключ на GitHub не настроен, используй HTTPS:

```bash
git clone https://github.com/Bogban893/Octopus_escape.git
```

> Чтобы отправлять изменения, нужен доступ к репозиторию: попроси владельца добавить тебя в Collaborators.

### 3. Установить Unity нужной версии

1. Открой Unity Hub → **Installs** → **Install Editor**.
2. Если `6000.6.3f1` нет в списке, открой вкладку **Archive** или страницу [unity.com/releases/editor/archive](https://unity.com/releases/editor/archive) и нажми **Install** у этой версии. Ссылка откроется в Hub.
3. Модули можно не выбирать: для разработки достаточно редактора под свою ОС.

### 4. Открыть проект

1. Unity Hub → **Projects** → **Add** → **Add project from disk** → выбери папку `Octopus_escape`.
2. Открой проект. **Первое открытие займёт 5–15 минут:** Unity скачивает пакеты и строит кэш в папке `Library/`. Это нормально.
3. Открой сцену: `Assets/Scenes/` → двойной клик по сцене.

## Настройка редактора кода

Без этого не будет подсказок и автодополнения, а писать код станет намного тяжелее.

### Rider (рекомендуем)

1. Установи Rider.
2. В Unity открой **Edit → Preferences → External Tools** (на macOS: **Unity → Settings → External Tools**).
3. В **External Script Editor** выбери Rider.
   - **Если Rider нет в списке** (так бывает, если он установлен вручную, например в `/opt` на Linux), выбери **Browse...** и укажи исполняемый файл:
     - Linux: `.../JetBrains Rider-<версия>/bin/rider.sh`
     - Windows: `C:\Program Files\JetBrains\JetBrains Rider <версия>\bin\rider64.exe`
4. Нажми **Regenerate project files**.

### VS Code

1. Установи расширение **Unity** от Microsoft. Оно само подтянет C# Dev Kit.
2. Установи [.NET SDK](https://dotnet.microsoft.com/download).
3. В Unity: **External Tools → External Script Editor → Visual Studio Code**, затем **Regenerate project files**.

### Проверка

Создай в `Assets/Scripts` скрипт (**Create → MonoBehaviour Script**), открой его двойным кликом и начни набирать `transform.`. Если появились подсказки, всё работает. Тестовый скрипт потом удали.

## Как тестировать мультиплеер

Мы используем **Multiplayer Play Mode**, чтобы запускать несколько игроков прямо в редакторе:

1. **Window → Multiplayer → Multiplayer Play Mode**.
2. Включи **Player 2**. Откроется второе окно игры.
3. Нажми **Play**: в одном окне выбери **Host**, в другом **Join**.

Проверяй фичи **со стороны клиента** (не хоста): большинство сетевых багов видно только там.

Подробнее о сети: [docs/NETWORKING.md](docs/NETWORKING.md).

## Как работаем вместе

### Перед началом работы

```bash
git pull
```

### Правила, которые спасут от боли

- **Перемещай, переименовывай и удаляй файлы только внутри Unity** (окно Project), а не в проводнике. У каждого файла есть парный `.meta` с ID, по которому на него ссылаются сцены. Потерянный `.meta` означает сломанные ссылки.
- **Всегда коммить `.meta` вместе с файлом.**
- **Не редактируйте одну и ту же сцену или префаб одновременно.** Unity не умеет нормально объединять сцены, поэтому договаривайтесь, кто над чем работает.
- **Перед коммитом** проверь, что в окне Console нет красных ошибок.
- Коммиты делай небольшими и с понятным сообщением: `feat: хватание предметов`, `fix: камера у клиента`.
- **Не создавай файлы, имена которых отличаются только регистром** (`Player.cs` и `player.cs`). На Linux это два разных файла, а на Windows один, и у второго участника всё сломается. Все имена пишем в PascalCase.
- **Тяжёлые файлы** (модели, текстуры, звук, шрифты, PDF) автоматически уходят в Git LFS, список форматов задан в `.gitattributes`. Если добавляешь новый тяжёлый формат, сначала допиши его туда.

### Что не попадает в git (и это правильно)

`Library/`, `Temp/`, `Logs/`, `UserSettings/`, `.idea/`, `*.csproj`, `*.sln` — это кэш и личные настройки, Unity и редактор создают их сами.

## Где что лежит

```
Assets/
├── Scripts/     — код (C#)
├── Models/      — 3D-модели (.fbx)
├── Materials/   — материалы
├── Textures/    — текстуры
├── Prefabs/     — готовые объекты (игрок, предметы, NPC)
├── Animations/  — анимации
├── Audio/       — звуки и музыка
├── Scenes/      — уровни
└── Settings/    — настройки графики (URP)
Art/Source/      — исходники ассетов (.blend), Unity их не импортирует
Tools/           — скрипты-помощники (например, экспорт из Blender)

ROADMAP.md       — план работ
```

- [docs/CONVENTIONS.md](docs/CONVENTIONS.md) — как называть файлы, классы и переменные.

## Частые проблемы

| Проблема | Решение |
|---|---|
| Модели розовые или пропали, `.fbx` весит ~130 байт | Не установлен Git LFS. Выполни `git lfs install`, затем `git lfs pull` |
| Unity предлагает обновить проект | Открыта не та версия Unity. Закрой без обновления и поставь `6000.6.3f1` |
| В Console куча ошибок после `git pull` | Подожди, пока Unity переимпортирует файлы. Если не помогло: **Assets → Reimport All** |
| Нет подсказок в коде | **External Tools → Regenerate project files**, перезапусти редактор кода |
| После `git pull` все файлы выглядят изменёнными (Windows) | Проблема с переводами строк. Выполни `git config --global core.autocrlf false`, затем `git checkout -- .` (⚠️ это сотрёт твои незакоммиченные изменения, сначала сохрани их) |
| `Filename too long` при клонировании (Windows) | `git config --global core.longpaths true` и короткий путь к проекту |
| Странные ошибки, которые ничем не лечатся | Закрой Unity, удали папку `Library/` и открой проект заново (кэш пересоберётся) |
