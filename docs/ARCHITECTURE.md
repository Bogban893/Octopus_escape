# Архитектура

Цель — код, в который легко добавлять новое (предметы, NPC, режимы), не переписывая старое.

## Главные принципы

### 1. Ввод отделён от логики

Осьминог не знает про клавиатуру. Он получает команды через интерфейс:

```
[Клавиатура/геймпад] → OctopusInputReader ─┐
                                           ├→ IOctopusInput → OctopusLocomotion, OctopusGrabber, ...
[ИИ / тест / реплей] → другой источник ────┘
```

Плюсы: легко сменить раскладку, сделать бота или тест, и ввод читается **только у владельца** осьминога в сети.

### 2. Маленькие компоненты вместо одного «бога»

Плохо: `Octopus.cs` на 2000 строк.
Хорошо: каждый компонент делает одно дело.

```
Octopus (префаб)
├── NetworkObject
├── OctopusInputReader     — читает ввод (только у владельца)
├── OctopusLocomotion      — движение тела
├── TentacleRig            — физика щупалец
├── OctopusGrabber         — хватание / бросок
├── OctopusCamouflage      — смена окраса
└── OctopusAnimator        — анимации
```

### 3. Интерфейсы для взаимодействия с миром

Осьминог взаимодействует не с «дверью» или «стаканом», а с интерфейсом:

| Интерфейс | Кто реализует | Зачем |
|---|---|---|
| `IGrabbable` | стакан, ключ-карта, врач (!) | можно схватить |
| `IInteractable` | дверь, сканер, кнопка | можно нажать E |
| `INoiseListener` | NPC | слышит шум |
| `IDetectable` | осьминог | NPC могут его заметить (учитывает окрас) |

Новый предмет = новый класс, реализующий интерфейс. Код осьминога не меняется.

### 4. Данные — в ScriptableObject

Числа и настройки не хардкодятся в скриптах, а лежат в ассетах, которые редактируются в Inspector:

- `OctopusConfig` — скорость, сила броска, радиус хватания.
- `ItemDefinition` — id, название, иконка, уровень доступа.
- `NpcConfig` — дальность зрения, угол обзора, скорость, характер.
- `GameModeDefinition` — правила режима.

Ассеты лежат в `Assets/Data/`.

### 5. Сервер — источник правды для мира

Мир (NPC, тревога, двери, цели) живёт на сервере (хосте). Клиенты только отображают его состояние.
Подробно — [NETWORKING.md](NETWORKING.md).

### 6. События вместо прямых ссылок

Глобальное состояние (тревога, цели, режим) хранится в серверных системах как `NetworkVariable`.
При изменении система поднимает обычное C# событие, на которое подписываются UI, звук, свет:

```csharp
// AlarmSystem
public event Action<AlarmLevel> LevelChanged;
```

UI не опрашивает систему каждый кадр, а система не знает про UI.

### 7. Машины состояний

Там, где поведение меняется по ситуации: NPC (патруль → погоня), тревога, игровой режим (подготовка → игра → итоги).

## Слои и зависимости

```
UI, Audio, VFX          ← только читают состояние и слушают события
   ↓
Gameplay (Octopus, AI, Interaction, Alarm, Objectives, Modes)
   ↓
Core (утилиты, базовые интерфейсы, StateMachine) + Network (подключение, спавн)
```

Правило: **нижний слой не знает о верхнем.** Core не ссылается на Gameplay, Gameplay не ссылается на UI.

## Структура папок

```
Assets/
├── Scripts/
│   ├── Core/           — общие утилиты, StateMachine, расширения
│   ├── Network/        — подключение, сессии, спавн игроков
│   ├── Input/          — OctopusInputReader, IOctopusInput
│   ├── Gameplay/
│   │   ├── Octopus/    — компоненты осьминога
│   │   ├── Tentacles/  — физика щупалец
│   │   ├── Interaction/— IGrabbable, IInteractable, двери, предметы
│   │   ├── AI/         — восприятие, состояния, типы NPC
│   │   ├── Alarm/      — система тревоги
│   │   ├── Objectives/ — цели и предметы побега
│   │   └── Modes/      — GameMode, LabEscapeMode
│   ├── UI/
│   └── Editor/         — инструменты редактора (не попадают в билд)
├── Data/               — ScriptableObject-ассеты (конфиги, предметы)
├── Prefabs/
├── Models/  Materials/  Textures/  Animations/  Audio/
├── Scenes/
│   ├── Bootstrap.unity — NetworkManager, стартовая сцена
│   ├── MainMenu.unity
│   └── Levels/         — Lab_Prototype.unity, ...
└── Settings/           — настройки URP
```

Папки создаются по мере необходимости, а не заранее.

## Пространства имён и сборки

- Namespace повторяет папку: `OctopusEscape.Gameplay.Octopus`, `OctopusEscape.Core`.
- Assembly Definitions (этап 1):
  - `OctopusEscape.Runtime` — весь игровой код;
  - `OctopusEscape.Editor` — `Scripts/Editor`, только для редактора;
  - `OctopusEscape.Tests` — тесты.

Сборки ускоряют компиляцию и не дают случайно сослаться на код редактора из игры.

## Сцены

- **Bootstrap** — загружается первой, содержит `NetworkManager` и всё, что живёт всю игру.
- **MainMenu** — меню, создание/вход в сессию.
- **Levels/** — уровни. Загружаются через сетевой менеджер сцен, чтобы у всех игроков была одна и та же сцена.
