## Этап 1. Сетевой фундамент

**Идея:** сеть закладывается с самого начала — переделывать одиночную игру в сетевую очень дорого.
Одиночная игра = хост без клиентов, то есть один и тот же код.
**Как:** Netcode for GameObjects (host/client), тест двух игроков в редакторе через Multiplayer Play Mode. См. [NETWORKING.md](docs/NETWORKING.md).

- [x] Assembly Definitions `OctopusEscape.Runtime` и `OctopusEscape.Editor`
- [x] Инструмент редактора «Octopus Escape → Save As Prefab» (обход проблемы drag & drop под Wayland)
- [x] Временное меню `NetworkDebugMenu`: кнопки «Host» / «Join»
- [x] Скрипт заглушки игрока `PlayerStub` (движение + цвет по ID игрока)
- [x] Тестовая сцена `Prototype/NetworkSandbox` с `NetworkManager` (разделение на Bootstrap / меню / уровни — этап 9)
- [x] Префаб `PlayerStub` (капсула) спавнится для каждого подключившегося
- [x] Проверено: 2 игрока в Multiplayer Play Mode видят друг друга

**Результат:** два окна редактора, каждый двигает свою капсулу, оба видят движение друг друга.

## Этап 2. Осьминог: передвижение и камера

**Идея:** управление осьминогом целиком (не отдельными щупальцами) — приятно и понятно.
**Как:** ввод отделён от логики (`IOctopusInput`), движение через `Rigidbody`, камера — Cinemachine. Владелец сам двигает своего осьминога (owner authority). См. [systems/octopus.md](docs/systems/octopus.md).

- [x] Правильный экспорт из Blender (скрипт `Tools/Blender/export_fbx.py`, Bake Axis Conversion)
- [ ] Импорт модели: Rig = Generic, масштаб ≈ 0.6 (размах около 1 м, D-006), материалы
- [ ] Префаб `Octopus` (модель + Rigidbody + коллайдер + NetworkObject)
- [ ] Свои Input Actions: Move, Look, Grab, Release, Camouflage, Interact
- [ ] `OctopusInputReader` → `IOctopusInput`
- [ ] `OctopusLocomotion`: движение WASD относительно камеры
- [ ] Камера от третьего лица (только для своего осьминога)
- [ ] Анимации `Idle` / `Crawl` по скорости
- [ ] `OctopusConfig` (ScriptableObject) — скорость, ускорение и т.д.

**Результат:** два игрока бегают осьминогами по тестовой комнате, у каждого своя камера.

## Этап 3. Физические щупальца (прототип)

**Идея:** щупальца живые и смешные — физика даёт это бесплатно.
**Как:** цепочка костей щупальца → `Rigidbody` + `ConfigurableJoint`. Физика щупалец локальная (косметика) на каждом клиенте, по сети синхронизируются только «намерения» (за что держимся). Сначала — эксперимент (spike), потом решение.

- [ ] Spike: одно щупальце на джоинтах, подобрать жёсткость/демпфирование
- [ ] Spike: альтернатива — IK + вторичная физика; сравнить
- [ ] Записать решение в [DECISIONS.md](docs/DECISIONS.md)
- [ ] `TentacleRig`: все 8 щупалец, общий конфиг
- [ ] Щупальца реагируют на движение тела и окружение

**Результат:** осьминог бегает, щупальца естественно болтаются и цепляются за пол, FPS стабильный.

## Этап 4. Хватание и бросок

**Идея:** главная механика — хватать, присасываться, кидать.
**Как:** ЛКМ — ближайшее подходящее щупальце само тянется к цели (`IGrabbable`). Схваченный предмет передаётся во владение хватающему игроку. См. [systems/interaction.md](docs/systems/interaction.md).

- [ ] Интерфейс `IGrabbable`, компонент `Grabbable`
- [ ] `OctopusGrabber`: поиск цели, выбор щупальца, захват / отпускание
- [ ] Бросок (с силой по зажатию?)
- [ ] Синхронизация захвата по сети
- [ ] Присасывание к поверхности (держаться на месте)

**Результат:** оба игрока могут поднять стакан, бросить его, и это видно обоим.

## Этап 5. Взаимодействия и предметы

**Идея:** мир реагирует: двери, ключ-карты, шум от предметов.
**Как:** `IInteractable`, данные предметов в `ItemDefinition` (ScriptableObject), шум — `NoiseEvent`, который слышат NPC.

- [ ] `IInteractable` + подсказка «Нажми E»
- [ ] `ItemDefinition`, инвентарь осьминога (минимальный)
- [ ] Ключ-карта + дверь с уровнем доступа
- [ ] Шум: упавший/брошенный предмет создаёт `NoiseEvent`

**Результат:** найти ключ-карту → открыть дверь. Брошенный стакан «шумит» (видно в debug).

## Этап 6. Охранник (ИИ)

**Идея:** стелс невозможен без того, кто ищет.
**Как:** логика NPC только на сервере. Восприятие (зрение-конус + слух), машина состояний, NavMesh. См. [systems/ai.md](docs/systems/ai.md).

- [ ] NavMesh на тестовой сцене, патруль по точкам
- [ ] `NpcPerception`: зрение (конус + raycast), слух (`NoiseEvent`)
- [ ] Машина состояний: Patrol → Suspicious → Investigate → Chase → Capture
- [ ] Индикатор заметности над NPC / на экране
- [ ] Поимка игрока

**Результат:** охранник патрулирует, идёт на шум, замечает и ловит осьминога.

---

## Этап 7. Игровой цикл: режим, победа, поражение

**Идея:** собрать всё в игру с началом и концом. Режим — отдельная сущность, чтобы потом добавить «Ограбление банка».
**Как:** `GameMode` (серверный NetworkBehaviour) + `GameModeDefinition` (ScriptableObject). См. [systems/game-flow.md](docs/systems/game-flow.md).

- [ ] `GameMode` базовый класс, `LabEscapeMode`
- [ ] Зона выхода = победа; все пойманы = поражение
- [ ] Экраны победы/поражения, рестарт
- [ ] Точки спавна (несколько вариантов старта)

**Результат:** полный забег: старт → ключ → дверь → выход (или поимка) → экран итогов.

## Этап 8. Тревога

**Идея:** лаборатория «помнит», что эксперимент сбежал.
**Как:** `AlarmSystem` на сервере, уровень тревоги — `NetworkVariable`. Подписчики: двери, NPC, свет, звук.

- [ ] Уровни: Calm → Suspicious → Alert → Lockdown
- [ ] Железные двери закрываются при Alert
- [ ] Сирена и красный свет
- [ ] NPC при тревоге ищут внимательнее

**Результат:** если заметили — меняется поведение уровня, побег становится сложнее.

## Этап 9. Игра через интернет

**Идея:** играть с другом не в одной сети.
**Как:** Unity Multiplayer Services (Sessions: Relay + Lobby) — без своего сервера и проброса портов.

- [ ] Подключить Unity Gaming Services к проекту
- [ ] Создание сессии / вход по коду
- [ ] Главное меню (Играть одному / Создать / Присоединиться)
- [ ] Обработка отключения игрока

**Результат:** два компьютера в разных сетях играют вместе по коду комнаты.
